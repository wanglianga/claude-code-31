# 囍宴云 · 城市婚礼宴会厅档期布置与临场变更协同平台

面向城市婚礼宴会厅的一体化管理页面：销售录入生成宴会项目 → 策划师厅内布置 → 婚前筹备串联 → 婚礼当天临场变更跨岗位协同 → 婚后归档复盘与争议处理。

## 原始需求

> 设计城市婚礼宴会厅档期布置与临场变更页面，可使用 Vue 3、TypeScript 和 Pinia。销售录入新人婚期、厅别、桌数、菜单、仪式需求、灯光音响、花艺、宾客动线和付款节点后，页面生成宴会项目。策划师根据厅内尺寸、舞台、主桌、迎宾区、儿童桌、老人席和摄影机位规划布置。婚礼前，页面需要把菜单试吃意见、桌数增减、酒水寄存、彩排时间、外部婚庆进场、消防通道和尾款支付串在一起。临场如果新人增加桌数、老人席换位、音响故障、外部花艺迟到、宾客过敏餐遗漏或婚礼仪式延迟，页面要让销售、策划、宴会经理、厨房和收银看到同一变更。变更会影响菜单备料、桌卡、服务员分区、灯光流程和结算金额。婚礼结束后，实际桌数、酒水消耗、临场加项、投诉、优惠和尾款收取都进入同一项目档案，方便后续复盘和客户争议处理。项目页还会保留每次客户确认的版本，婚礼后处理投诉时能区分原计划、彩排调整和现场临时要求。页面还要把婚礼当天临场变化转成跨岗位任务，厨房、宴会经理、策划和收银看到的不是孤立备注，而是会影响备料、服务和结算的变更。

## 技术栈

- **前端**：Vue 3 + TypeScript + Pinia + Vue Router + Vite（SVG 厅内布置图编辑器，拖拽摆台）
- **后端**：Node.js + Express + TypeScript（临场变更影响引擎、结算计算、版本快照）
- **数据库**：PostgreSQL 16（仅 compose 内部网络访问，不发布宿主端口）
- **部署**：多阶段 Dockerfile（非 root 运行 + HEALTHCHECK）+ docker compose 一键启动

## 快速开始（Docker 一键部署）

```bash
cp .env.example .env        # 可选：按需修改端口/密钥
docker compose up -d        # 构建并启动 app + db
docker compose ps           # 确认 app 为 healthy
```

- 应用访问：`http://localhost:${CC_PUBLISH_PORT}`（默认 8080；本任务验证时 `CC_PUBLISH_PORT=3031`）
- 实际映射端口可用 `docker compose port app 3000` 查看
- 首次启动自动建表并注入演示数据（设置 `SEED_DEMO=false` 可关闭）
- 停止：`docker compose down`（加 `-v` 可同时清空数据卷）

**验证方式**：本系统以「宿主 `docker compose up -d` 启动成功、app 容器 healthy、关键业务流（登录 → 建项目 → 临场变更生成跨岗位任务 → 结算联动 → 版本留存 → 婚后归档）可在浏览器/接口走通」为验证通过标准。

## 核心业务流程（建议演示路径）

1. **销售录入**：`sales01` 登录 → 宴会项目 → 新建宴会项目（婚期/厅别/桌数/菜单/仪式需求/灯光音响/花艺/宾客动线/付款节点）→ 自动生成项目与「原计划」版本 V1
2. **策划布置**：`planner01` 登录 → 项目详情 → 厅内布置 → 一键摆台 / 拖拽舞台、主桌、迎宾区、儿童桌、老人席、摄影机位 → 保存布置图
3. **婚前筹备**：项目详情 → 婚前筹备，逐项跟进菜单试吃意见、桌数增减、酒水寄存、彩排时间、外部婚庆进场、消防通道、尾款支付
4. **临场变更**：项目详情 → 临场变更 → 发起变更（如「增加桌数」2 桌）→ 系统自动生成厨房备料、宴会经理摆台分区、策划更新布置图、收银结算追加四类任务，桌数与应收金额同步联动
5. **过敏餐跟踪**：项目详情 → 过敏餐 → 登记过敏宾客（姓名/桌号/禁忌食材/替代菜品）→ 厨房确认后自动生成服务员桌边提醒；临场换桌时过敏餐提示随宾客移动并同步桌卡、厨房出餐与服务员分区；上错菜可登记事故并记录客户沟通处理结果
6. **跨岗位协同**：分别用 `kitchen01` / `manager01` / `planner01` / `cashier01` 登录，在任务中心或项目变更页处理各自任务；全部完成后变更自动结案
7. **客户确认版本**：项目详情 → 确认版本 → 生成「彩排调整」或「现场临时」版本；可随时查看快照、与当前方案对比差异
8. **结算收款**：`cashier01` → 结算支付 → 尾款收款（到账后「婚前筹备 · 尾款支付」自动完成）
9. **婚后归档**：`manager01` → 婚后档案 → 录入实际桌数、酒水消耗、临场加项、投诉（关联版本来源）、优惠与复盘笔记 → 归档后结算按实际桌数重算，投诉处理可对照版本来源定责

## 过敏餐跟踪

| 环节 | 系统行为 |
| --- | --- |
| 新人提交名单 | 记录宾客姓名、桌号、禁忌食材、替代菜品，自动生成厨房备餐确认任务并同步服务员线 |
| 厨房确认 | 厨房在过敏餐页或任务中心确认 → 自动生成服务员桌边提醒（服务员角色任务，服务员登录可见） |
| 临场换桌 | 过敏餐提示随宾客移动：未完成任务的桌号自动替换，并生成桌卡更新、厨房出餐桌号变更、服务员分区同步任务 |
| 上错菜 | 任意岗位可登记事故 → 生成宴会经理处理任务，事件进入客户沟通记录 |
| 沟通处理 | 宴会经理登记客户沟通结果 → 写入事故事件的沟通记录并结案 |
| 三视图联动 | 厨房出餐单、服务员分区提醒、桌卡提示同源实时联动，婚礼当天换桌可持续追踪 |

## 目录结构

```
├── Dockerfile              # 多阶段：前端构建 → 后端构建 → 非 root 运行时（HEALTHCHECK）
├── docker-compose.yml      # app（唯一对外端口）+ db（仅内部网络）
├── .env.example            # 环境变量样例
├── server/                 # Express + TypeScript 后端
│   └── src/
│       ├── index.ts        # 入口：静态托管 + SPA 回退 + 启动迁移/种子
│       ├── db.ts           # pg 连接池 + 建表迁移
│       ├── seed.ts         # 演示数据（账号/厅/菜单/三阶段项目）
│       ├── auth.ts         # scrypt 密码哈希 + HMAC 令牌
│       ├── impacts.ts      # 临场变更 → 跨岗位任务/结算影响引擎
│       ├── settle.ts       # 结算计算（桌数×单价+变更+加项-优惠）
│       └── routes.ts       # 全部 REST API
└── web/                    # Vue 3 + TS + Pinia 前端
    └── src/
        ├── views/          # 登录/仪表盘/档期/项目列表/项目详情/任务中心
        ├── components/     # Modal、FloorPlan（SVG 布置图编辑器）
        └── components/tabs/# 项目详情八个标签页
```
